# Superpowers parity and intentional deviations

This is the capability-by-capability parity review for Issue #15. It compares
the canonical, portable workflow in this repository with the upstream
[Superpowers](https://github.com/obra/superpowers) Skills at commit
[`b36e0829c6d0140e93cfef2ca599b1b07d4a7797`](https://github.com/obra/superpowers/tree/b36e0829c6d0140e93cfef2ca599b1b07d4a7797)
(inspected 2026-08-31). The review covers every workflow Skill in that
revision, rather than assuming that the workflow described in its README is
complete.

## How to read the matrix

- **Full semantic parity** means the same engineering guarantee is required.
- **Parity with intentional implementation deviation** means the guarantee is
  retained but the repository deliberately uses a different, portable form.
- **Intentional non-parity** means the upstream facility is not adopted; the
  rationale and compensating control are stated in the row.

The comparison is about engineering guarantees, not command, directory, or
agent-framework compatibility. The [capability contract](capability-contract.md)
and [canonical methodology](methodology.md) are the normative local sources.

## Result and safeguards

All fourteen upstream workflow Skills are represented above. No upstream
engineering guarantee is omitted without an explicit intentional-deviation
entry and rationale. The recurring deviations are deliberate: this repository
uses native-first capability selection, durable GitHub work state, proportionate
process, and a human-only merge boundary instead of a prescriptive agent
orchestration layer.

The deviations retain the relevant guarantees through these controls:

- [`methodology.md`](methodology.md) requires design and planning when material,
  isolation for write-heavy work, independent review, and observed verification.
- [`capability-contract.md`](capability-contract.md) requires native-capability
  detection before the narrowest portable fallback, rather than custom
  replacement infrastructure.
- [`security-and-autonomy-boundaries.md`](security-and-autonomy-boundaries.md)
  reserves merge, release, and other sensitive actions for human approval.
- [CI validation](../.github/workflows/validate.yml) and the [behavioral
  evaluation harness](../evals/README.md) make packaging and workflow behavior
  independently checkable.
